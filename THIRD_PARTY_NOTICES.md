## URW Core 35 fonts

Unmodified files: `assets/fonts/urw-core35/*.otf`, fourteen of the thirty-eight
faces of version 2.00. They are the metric-compatible substitutes for the
fourteen standard PDF fonts (NimbusSans for Helvetica, NimbusRoman for Times,
NimbusMonoPS for Courier, StandardSymbolsPS for Symbol and D050000L for
ZapfDingbats), and the renderer draws with them when a document references one
of those without embedding a program. The same content travels compressed in
`lib/src/render/resources/standard_font_programs_vm.dart`, generated by
`tool/generate_standard_fonts.dart`; the compression is the only difference
from the original files.

The programs stay under SIL OFL 1.1 — travelling beside MIT code does not
relicense them, and the OFL does not reach the documents drawn with them. The
full licence text accompanies the files in
`assets/fonts/urw-core35/LICENSE.OFL` and is reproduced further down, in the
ABeeZee test font section. URW++ also published the same fonts under AGPL3 and
LPPL 1.3c, as `assets/fonts/urw-core35/LICENSE.md` records, leaving the choice
to whoever redistributes them; this package chooses the OFL, and it is the OFL
text that travels with the files.

The copyright statement declares no Reserved Font Name, so the family names can
be carried as they are.

Copyright (c) 2014,2015 by (URW)++ Design & Development

## Brotli decoder

Files: `lib/src/io/codec/brotli/` (except `brotli.dart`, which is this
package's own facade).

A Dart port of the Brotli reference decoder, `org.brotli.dec`, written by the
Brotli Project at Google. The port came from a sibling project by the same
author and was copied here with the file names adjusted to Dart convention and
without `Decoder.dart`, which depends on `dart:io` and would cost this package
its `dart2js` and `dart2wasm` support. The decoding logic was not changed.

The decoder is used only to expand the table data of a WOFF 2.0 font, as the
W3C recommendation requires. The static dictionary of RFC 7932 Annex A is
embedded in `dictionary_data.dart` and is indispensable: without it, valid
streams simply do not decode.

## PDF Association PDF 2.0 example

Unmodified file: `test/assets/pdf20-offset-start.pdf`, a byte-for-byte copy of
`PDF 2.0 with offset start.pdf` from the PDF Association's example repository.
Only the file name changed, to keep spaces out of the path; the content is
identical (SHA-256 in `test/assets/manifest.json`).
Source: https://github.com/pdf-association/pdf20examples

It is the official example of the ISO 32000-2, 7.5.2 provision that allows
arbitrary bytes before `%PDF-`: the header starts at byte 656 and the
cross-reference offsets are counted from the percent sign. It is the fixture
for `test/kernel/pdf/reader_offset_start_test.dart`.

Attribution-ShareAlike 4.0 International (CC BY-SA 4.0), which permits
redistribution, commercial included, provided the credit above is given and
this file stays under the same licence. CC BY-SA 4.0 covers this file only; it
does not extend to the rest of the package. Full terms:
https://creativecommons.org/licenses/by-sa/4.0/legalcode

## Ghostscript Tiger (AGPL)

`test/assets/ghostscript-tiger/ghostscript-tiger.svg` comes from Ghostscript,
by way of Wikimedia Commons, under the **GNU Affero General Public License** —
it is the one illustration in this repository that is not public domain. The
full licence text and the provenance sit in that directory, in
`LICENSE.AGPL-3.0.txt` and `NOTICE.md`.

The directory is checked into git, so the suite runs from any clone, and it is
listed in `.pubignore`: **this file is not in the package published to
pub.dev**. Including it would be mere aggregation (AGPL-3.0, section 5), but an
AGPL file inside an MIT package trips the licence scanners that consumers run
in continuous integration, and there is no reason to impose that on someone who
only wants the library.
